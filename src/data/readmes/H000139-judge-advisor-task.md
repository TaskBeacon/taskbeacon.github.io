# Judge–Advisor System — browser companion

Canonical: [T000139](https://github.com/TaskBeacon/T000139-judge-advisor-task). Open the shared [runner](https://taskbeacon.github.io/psyflow-web/?task=H000139-judge-advisor-task). Version 0.1.0; Chinese, SimHei; behavioral task; updated 2026-08-31.

## 1. Task Overview

This source-only browser port preserves the canonical two-pass adaptation with openly disclosed mechanical advice. Participants first estimate twelve historical years independently. Only after all initial responses are complete does the task replay the same questions with the participant's original estimate and computer-generated advice. Advice is not a human recording and may be wrong. The original Chinese items are fact-checked but not psychometrically validated. The task has no clinical interpretation or established validity as a measure of trust in human advisers.

## 2. Task Flow

![Task Flow](task_flow.png)

All twelve initial estimates are collected first, with a maximum of 45 seconds per question. A transition screen precedes the revision pass. Each available item shows advice for 3 seconds, followed by a blank final-response field with a 45-second deadline; the initial estimate and advice remain visible. Neutral recording notices last 0.3 seconds. A missing or invalid initial estimate, or advice outside the numeric domain, produces a 1-second notice without advice or final capture. Task stages display no truth, correctness, rewards or numeric defaults. The shared operator export panel after task completion displays analysis fields, including truth, and should be treated as an operator interface rather than participant feedback.

## 3. Configuration Summary

`config/config.yaml` is byte-identical to T. One logical block contains twelve paired items visited in two passes. Near, intermediate and far distances are balanced with directions toward and away from truth. The offset sets are 15/18/20, 40/43/45 and 70/72/75 years. Subject IDs 101–999 determine reproducible assignments. Input uses signed integers in the common domain ±1,000,000,000; zero and negative values remain valid, with a separate year-plausibility flag.

Signed weight of advice is `(final-initial)/(advice-initial)`. Negative values and values above one remain unchanged. Zero advice distance produces null weights and an explicit reason. Signed and absolute revisions, the separate absolute revision ratio, self weight, absolute errors and accuracy gain are exported with the original values and validity states. Toward advice can overshoot truth; no accuracy benefit is promised. Browser-recorded `enter` is the documented alias of native `return`.

## 4. Methods (for academic publication)

The browser version preserves the canonical trial contract based on [Yaniv (2004)](https://doi.org/10.1016/j.obhdp.2003.08.002), Study 3 mechanical advice, with documented adaptations to materials, localization, timing, disclosure and incentives. See the canonical [source audit](https://github.com/TaskBeacon/T000139-judge-advisor-task/blob/main/references/task_logic_audit.md) and [materials](https://github.com/TaskBeacon/T000139-judge-advisor-task/blob/main/references/materials.md). The shared runtime owns rendering, input, trigger notifications, raw stage records and paired reduction.

Each initial segment and its later revision share one helper-issued logical trial ID. Initial units remain in the shared recorder although the first segment is excluded from reduced output; the final segment produces one paired row. Initial fields survive unchanged. Raw JSONL groups records by logical ID, so chronology requires `onset_time_monotonic_s`, not line order. `pair_complete` means both passes were processed, not that both answers were valid.

Unlike the native task's separately saved initial-pass CSV, browser state remains in memory until completed or supported aborted export. Closing or crashing the browser has no validated disk-recovery guarantee. There is no claim of hardware timing, physical display calibration or OS IME validation.

The full production browser session used twelve pairs and unchanged deadlines. Actual downloads contained twelve reduced rows and 59 raw stages; canonical scoring, all initial fields, natural draft timeouts, zero, invalid entries and weights of −1 and 2 were verified. Inputs were generated by the operator for validation and are not participant observations. See [validation](references/validation/README.md) and the [alignment boundary](transfer_node.md).

The notification workflow dispatches updates to the shared runner. `TASKBEACON_ORG_DISPATCH_TOKEN` requires target-repository Contents read/write permission; Actions write alone is insufficient, and organization approval may be required. There is no per-task app shell or dependency installation.
